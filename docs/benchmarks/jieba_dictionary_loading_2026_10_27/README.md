# Jieba dictionary loading qualification

This is a bounded component comparison for
[#1279](https://github.com/nowledge-co/hawdb/issues/1279), based on main
`75b87bac8`. [The probe](probe.rs) is an unregistered developer executable.
Its temporary manifest enables the original Jieba dictionary feature only to
construct the baseline, outside HawDB's workspace and dependency graph. Do not
register it in CI or include it in a published library archive.

The candidate calls the actual production `cjk_dictionary::load` function.
Both implementations use Jieba 0.11.0 and the complete, unmodified 349,045-entry
dictionary. The candidate streams that resource through Zstd 0.14.3 into
Jieba's public `with_dict` API. [Resource identity and license](../../../crates/search/src/data/README.md)
are part of the Search package, not runtime configuration.

## Evidence

[results.json](results.json) records source hashes, raw measurements and the
five-lock dependency audit. The upstream and candidate produce equal complete
Token values, including scalar and byte offsets, for:

- 698,090 dictionary-word cases: every word with HMM enabled and disabled;
- 7,198 mixed phrase cases: adjacent dictionary words sampled every 97 entries,
  ASCII compounds and supplementary Han, with both HMM modes;
- 48 baseline token/offset cases retained as ordinary Search regressions.

Both loaded dictionaries report 349,045 records and total frequency 60,101,964.
The complete word-output fingerprint is
`98656a1aec1b07c37baf1db9cbe652af896417f3f07debe59d6cad15d359a653`.
The original input contains no duplicate words or non-ASCII whitespace. The
two public loading paths therefore receive identical ordered word/frequency/tag
entries. The analyzer fingerprint is unchanged.

Three fresh processes per mode were measured sequentially on macOS arm64,
Rust 1.97.1, using the repository's ordinary checked development profile.
The shared allocation probe counts requested Rust capacity and conservatively
charges old/new reallocations together. It excludes native Zstd workspace,
allocator overhead and process RSS.

| Fixed dictionary / Rust allocation counter | Upstream default loader | Production streaming loader |
| --- | ---: | ---: |
| Retained bytes after construction | 34,070,024 | 29,887,224 |
| Peak bytes during construction | 34,083,600 | 38,415,185 |
| Bytes still retained after dropping Jieba | 8,388,608 | 0 |

The streaming path avoids the upstream process-lifetime decoded-source buffer.
Its public loader grows dictionary vectors rather than using the default
loader's preallocation, increasing temporary peak allocation. Both costs are
shown; lower retained bytes do not establish a lower initialization peak.
The three unoptimized-for-benchmark initialization samples are observational,
not a release startup, query throughput, cold-cache or RSS claim. This is not
complete-corpus BM25 or Windows qualification.

The package check includes the compressed resource and its MIT notice. An
independent consumer compiles the extracted Search archive and performs a
positive Han-language text search. That fixture uses temporary local paths for
unreleased HawDB dependencies only; it does not patch Jieba, Zstd or any other
registry dependency. Package publication remains separate.

## Replay and regeneration

Run from the repository root so Cargo uses the pinned toolchain and the same
repository profiles. The temporary manifest must remain outside the checkout.

```sh
repo_root="$(git rev-parse --show-toplevel)"
probe_dir="$(mktemp -d)"
cat >"$probe_dir/Cargo.toml" <<EOF
[package]
name = "hawdb-dictionary-proof"
version = "0.0.0"
edition = "2024"
publish = false
[workspace]
[[bin]]
name = "dictionary-proof"
path = "$repo_root/docs/benchmarks/jieba_dictionary_loading_2026_10_27/probe.rs"
[dependencies]
jieba-rs = "=0.11.0"
zstd = "=0.14.3"
serde_json = "=1.0.154"
hawdb-integrity = { path = "$repo_root/crates/integrity" }
EOF
git show 75b87bac8:Cargo.lock >"$probe_dir/Cargo.lock"
CARGO_BUILD_JOBS=2 cargo build --manifest-path "$probe_dir/Cargo.toml" --bin dictionary-proof
probe="$probe_dir/target/debug/dictionary-proof"
asset="$repo_root/crates/search/src/data/jieba-0.11.0.dict.txt.zst"
"$probe" default "$asset"
"$probe" streamed "$asset"
"$probe" parity "$asset"
"$probe" golden "$asset" "$probe_dir/golden.json"
```

The `compress` mode accepts the original `jieba-rs-0.11.0/src/data/dict.txt`
from the pinned registry source and an output path. It prints both hashes and
lengths. The recorded resource regenerated byte-for-byte using streaming level
`0` and bundled Zstd 1.5.7. Do not edit or normalize the decompressed dictionary.

Ordinary CI retains its existing Search feature matrix and opaque allocator
target. The new byte-identity and golden tests run there; the baseline probe
and its older dependencies do not.
